# Use ZIP directory releases with file-level incremental updates

The user requires extract-and-run ZIP releases, not installers or self-extracting single executables, while retaining in-app updates. Each release owns an explicit SHA-256 file manifest; CI publishes a full ZIP and, when a preceding ZIP manifest exists, a delta ZIP containing changed files. Matching the baseline and hashing installed files permits a delta; otherwise the updater uses the full ZIP. This keeps the existing Electron runtime when unchanged without the extra complexity of binary patching (a changed app.asar is downloaded in full).

The updater stages and verifies before the user chooses restart. A Windows helper waits for exit, backs up only managed destinations, applies replacements and removals, and commits the manifest last; ordinary application failures trigger rollback. User files, settings and game directories are not release-owned. Recovery records and backups are retained in the tool's user-data directory; power loss or forced termination of the helper can require manual recovery from that backup or re-extraction of the full ZIP. Release 0.1.3 and earlier require a one-time manual migration because their updater only opens a browser.
